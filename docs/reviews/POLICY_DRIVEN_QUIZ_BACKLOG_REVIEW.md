## 2. Scope and methodology

### Sources inspected

1. The complete architecture document, including invariants, product scenarios, migration phases, decisions, and completion criteria.
2. #472 body and all three comments.
3. All native parents, delivery children, decisions, conformance issues, and operations issues through #679.
4. Every direct compatibility, foundation, superseded, security, analytics, testing, flashcard/Learning, and operational dependency retained in the programme closure.
5. Native parent/sub-issue relationships, labels, milestones, comments, state, and closing-PR references through GitHub CLI and GraphQL.
6. Current attempt, quiz, question, repetition, security, analytics, OpenAPI, migration, and test code.
7. AGENTS.md, docs/github-issue-guide.md, docs/open-issue-roadmap.md, and the prior report.

### Method

- The Git revision and worktree were frozen before issue analysis.
- A read-only issue closure was collected to /private/tmp/policy-driven-backlog-review/v2. Temporary scripts and snapshots are outside the repository.
- The architecture was normalized into 47 stable invariants before evaluating issue coverage.
- Native graph edges and body references were evaluated separately. A native parent is hierarchy, not an implementation prerequisite.
- Closed issue state was never treated as implementation evidence; code, migrations, tests, and linked closing PRs were checked.
- Issue-declared review budgets were parsed mechanically. Undefined and threshold-clustered estimates were then challenged against the claimed outcomes and current package surface.
- No issue, comment, label, milestone, source, migration, test, configuration, architecture document, PR, or remote state was changed.

### Limitations

- Issue text is mutable; this is a 2026-08-08 snapshot.
- No programme issue has a native closing PR. This proves only the absence of a native closing link, so source/history evidence was also inspected.
- Future LOC cannot be measured exactly. Numeric ranges are review-cost estimates; declarations at exactly 750 lines are warnings, not proof.
- A full Maven run was unnecessary because runtime code is unchanged. Current tests are evidence of the legacy baseline, not evidence that planned architecture exists.
- Product choices remain owner decisions. Recommendations identify fail-closed defaults and owners without deciding product behavior.

5. Do not split vertically by entity/repository/service/controller unless each merge enforces a safe independent invariant and has a real consumer.
6. PR descriptions report actual category totals and explain variance from issue estimate. Generated, vendored, mechanical deletion, and rename-only changes are reported separately.

8. Parent checklists update only after child verification and merged compatibility evidence.
9. A non-blocking size-warning action is useful, but it should classify generated/lock/vendor/mechanical files and warn—not fail—on total lines. Semantic review remains authoritative.
